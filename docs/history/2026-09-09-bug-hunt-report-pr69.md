## Notes & unverified leads
Leads that were examined but do not meet the "proven defect" bar. None is reported as a finding.

- **Per-`message_start` full-transcript `store.save()` (Info/efficiency).** The new `chat-usage` handler (`server.js:1164-1175`) calls `store.save()`, a synchronous `writeFileSync` of the entire transcript (`server.js:197-215`), once per API request inside a turn (the stdout `data` handler is the hot path). Before this PR, saves happened on `chat-message` / `chat-turn-end` only. Correctness is unaffected (single-process writes cannot interleave); a long image-heavy session multiplies per-turn disk I/O. If it ever bites, the fix is debounce/coalesce saves or skip persisting when usage is unchanged.
- **First `chat-usage` of a session can be dropped on startup (Low, pre-existing pattern).** The browser creates session state only after `POST /chat/start` resolves (`chat.js:324-360`), while the server broadcasts `chat-started` and the activation-prompt usage may arrive first (`server.js:1341,1168`); the event then hits `events.js:107-109` (`getSessionState` → null) and is dropped. HUD shows "—" until the next `message_start`. Same race as all other chat events; self-heals.
- **Pre-existing dangling path in `src/agents/syn.md:265`** — `Reference `specific_instructions/syn/brainstorm.md`` is the only reference in the four PR-touched agent files missing the `.claude/agents/` prefix. Pre-dates the PR; left untouched to keep the fix list PR-scoped.
- **HUD context window hardcoded to 200K** (`hud.js:49`) — acknowledged follow-up in the PR body; a session model is not yet tracked in session state. Not a regression.

### Refuted leads (proven not bugs)
- **Cache-token double count in the HUD.** `totalInput = inputTokens + cacheReadTokens + cacheCreationTokens` (hud.js:50) looked like it would over-count. Anthropic's prompt-caching docs define `input_tokens` as only the tokens *after the last cache breakpoint* and give `total_input_tokens = cache_read + cache_creation + input_tokens`. The sum is correct.
- **Subagent `message_start` mis-attributed to the parent session's HUD.** `chat-session.js:243-258` emits usage for every `message_start` tagged with the parent `sessionId` with no subagent check. Inspection of the installed Claude Code CLI binary (v2.1.220) shows `--forward-subagent-text` forwards subagent output as top-level `type: "assistant"`/`"user"` events with `parent_tool_use_id` set — it does **not** forward the subagent's raw `stream_event`/`message_start` frames into the parent stream, so the parser cannot see subagent usage. Refuted at the code/CLI-contract level (no live trace; residual risk if a future CLI version forwards subagent SSE frames).
- **Stale HUD after switching session tabs.** Renders `getActiveSession()`; `switchSession`/`endSessionTab`/`startNewSession` all call `loadSessionWorkspace`, which calls `renderHud()` (`state.js:342`). Refuted.
- **Plain Chat card removal left dangling references.** Zero `Plain Chat` / `plain-chat` / `agent-card-plain` matches in `src/`, `tools/`, or `docs/`; all three `startNewSession` callers are intact. Refuted.
- **`[FF]` menu-token collision.** No `ff` command file, agent, or JS token exists; `syn.md:110` enumerates single-letter and two-letter sets disjointly. Refuted.
- **Swarm/Free Form install-path breakage.** All `.claude/agents/...` references in the four agent files resolve in the installed layout (installer copies `src/agents/` wholesale); manifest `file: "03-protocols/swarm.md"` matches the real page; both installed docs copies verified. Refuted.
- **`message_start` early-return regression.** The old code returned early for `message_start`/`message_delta`/`message_stop` too; the new branch only adds a usage emit then returns. 12-edge-case harness + 9 new vitest cases all pass; pre-existing event types (`chat-token`, `chat-tool-use`, `chat-block-stop`, `chat-message`, `chat-turn-end`, `chat-init`) unaffected.
