# Notebook execution (shards runtime)

Developer notes for the notebook tools that drive a Jupyter kernel for the `notebook-walkthrough` skill (which needs Studio running for its panel, see `studio.md`) and for any agent that runs notebook cells. Covers `runtime/notebook/kernel.py`, the `notebook_*` MCP tools, and the `notebook-walkthrough` command. Describes what the code does today. Open items are marked `OPEN` or `TODO(owner: proflandrigan)`.

## 1. Purpose

Notebook cells run in a persistent kernel, one per session, so variables survive between calls. Agents do not run notebook code through ad-hoc Bash or a direct Python call. All execution goes through the tools below.

- Helper: `runtime/notebook/kernel.py`, a `jupyter_client` kernel wrapper.
- Per-session state: `.shards/notebooks/<session>/` under the project root.
- No shell is used. Python is discovered as `python3`, then `python` (`py` on Windows). Set `SHARDS_PYTHON` to override.

## 2. MCP tools

| Tool | Input | Behaviour |
|------|-------|-----------|
| `notebook_start` | `notebook`, `session?` | Starts a kernel for the `.ipynb` file. Creates the session state directory. |
| `notebook_exec` | `session`, `cell` | Runs one cell by index and returns its outputs. |
| `notebook_run_all` | `session` | Runs every cell in order. |
| `notebook_stop` | `session` | Shuts the kernel down. |

If `jupyter_client` or `ipykernel` is missing from the chosen interpreter, each tool fails (`isError`) with an install hint instead of running. The hint names the interpreter it checked:

```
Notebook tools need jupyter_client and ipykernel in the interpreter "python3". Install with: python3 -m pip install jupyter_client ipykernel (or set SHARDS_PYTHON to an interpreter that has them). If pip reports "externally-managed-environment" (Homebrew or another PEP 668 Python), create a project virtual environment instead: python3 -m venv .venv && .venv/bin/pip install jupyter_client ipykernel - then point Shards at it with the absolute path, e.g. export SHARDS_PYTHON="$PWD/.venv/bin/python", in the environment the host (and so the Shards MCP server) is launched from, and restart the session.
```

On Windows the venv paths are `.venv\Scripts\pip` and `.venv\Scripts\python.exe`. If no interpreter is found at all, the hint says so and gives the same venv route.

How `SHARDS_PYTHON` is read: the MCP server reads it from its own process environment on every notebook tool call (`findPython` in `runtime/notebook/index.js`). It is not read from `shards.config.yaml`. Set it in the shell that launches the host (the host passes it to the server it starts), or in the server's `env` block in the host's MCP config, then start a new session. Use an absolute path: discovery runs the interpreter from the server's working directory, not necessarily the project root.

Homebrew Python on macOS is externally managed (PEP 668), so `python3 -m pip install ...` fails with `externally-managed-environment`; the venv route above is the fix.

Errors from the kernel helper (`{ok: false, error}` from `kernel.py`, for example "kernel not alive" after `notebook_stop`, or "session not started") are returned as MCP errors (`isError: true`) with the text `<tool> failed: <error>`. The messages name the MCP tool to call next (`notebook_start`, or `notebook_run_all`, which restarts the kernel). Cell exceptions are not tool errors: `notebook_exec` returns them as a normal result with the cell's error output.

## 3. Walkthrough

The `notebook-walkthrough` skill is the entry point. It is generated by `build/skills.js` (`notebookSkill`) from `core/protocols/notebook_walkthrough.md` and the per-agent walkthrough modes (for example `core/agents/syn/modes/notebook_walkthrough.md`); do not edit generated output. The user picks a notebook and an agent (Data Scientist, ML Engineer, or Syn). The agent then reads its walkthrough file and runs the shared protocol. It uses `notebook_start` once, `notebook_exec` per cell, and `notebook_stop` at the end.

The walkthrough is conversational. It has no phases and no gates, and it writes no `project-specs.md`. Cells are not changed without explicit user confirmation.

## 4. UI (optional)

The walkthrough runs in chat-only mode. When the Shards UI is running, it can show the watched state file at `<project>/.shards/notebook-walkthrough.json` in the `notebook-walkthrough` panel. Without the UI the state file is still written and the chat carries on.

## 5. Failure modes

| Symptom | Cause | What to do |
|---------|-------|------------|
| Install hint returned | `jupyter_client` or `ipykernel` not installed in the chosen Python. | Run the `pip install` line in the project's environment. |
| `error: externally-managed-environment` from pip | Homebrew or another PEP 668 Python refuses global installs. | `python3 -m venv .venv && .venv/bin/pip install jupyter_client ipykernel`, then set `SHARDS_PYTHON` to the absolute path of `.venv/bin/python` and start a new session. |
| Wrong Python used | `python3` on PATH is not the project's interpreter. | Set `SHARDS_PYTHON` to the right executable. |
| `notebook_exec failed: session not started` | `notebook_start` not run for that session id. | Call `notebook_start`. |
| `notebook_exec failed: kernel not alive` | Session stopped (`notebook_stop`) or the kernel exited. | Call `notebook_start` (new kernel), or `notebook_run_all` to restart and re-run every cell. |
| Kernel state lost | Kernel stopped, or the process ended. | Run `notebook_start` and re-run the cells you need. |
| No interpreter found on Windows | Discovery tries `python3`, `python`, then `py`; none resolved on PATH. | Set `SHARDS_PYTHON` to the full interpreter path. |
